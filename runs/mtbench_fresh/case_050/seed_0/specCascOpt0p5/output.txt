For two arrays we can use the classic **two‑pointer** technique – once the two arrays are sorted they run the same way that a merge of two sorted lists will appear.  
If the two arrays are sorted in‑place, the final two‑pointer walk is linear and no extra data structures (besides the two input arrays) are required.

---

### Algorithm
```
build two arrays A[0 … n-1] and B[0 … n-1] (ascending)

0.   sort A and B in place (O(n log n) time, O(n) extra memory)
1.   i = 0, j = 0
2.   while i < n and j < n:
        if   A[i] == B[j]   →   print A[i] and  i++;  j++
        else if A[i] < B[j]   →   print A[i] (should be {A[i] + B[j]})
           i++                 →   j++
        else               →   j++
```

*Return* – every element that appears in the common list is printed; the arrays are printed once only (not duplicated).

### Correctness proof

We prove that the algorithm always prints the common elements.

**Lemma 1**  
During the algorithm the pointers `i` and `j` remain unchanged.
At each iteration there is a value `A[i]` that is minimal among `A[i]` and all keys,
and `B[j]` similarly
and `B[j]` is the minimal element of `B[j]` that has not yet been sorted.

*Proof.*  
During step‑2, if `A[i] == B[j]`, we are guaranteed that the corresponding element belongs to both lists.  
If `A[i] < B[j]`, we advance `i` until the smaller element of the two arrays is seen.  
If `B[j] > A[i]`, we advance `j` until the comparison is possible.  
Thus every iteration keeps each pointer to the smallest element of the four unsorted elements. ∎



**Lemma 2**  
Consider all elements that appear in both lists.  
If `x` is an element `A[i] == B[j]` that is found, the algorithm will output `x`.  
If two elements of `A[i]` equal a particular element of `B[j]`, the algorithm counts the *exact* number of times it appears in the other list, consistent with the algorithm's reference style.

*Proof.*  
The algorithm moves `i` and `j` only when they refer to the same element.  
Because `A` and `B` are sorted, any element is compared to the corresponding next element in the *other* list.  
When all positions of the same value are encountered, it is printed one time each for each copy – i.e. the multiplicity effect.  
Thus every element that appears in both lists is printed exactly once. ∎



**Theorem**  
The algorithm prints all pairs of elements that are present in both arrays.

*Proof.*  
By Lemma&nbsp;1, after the algorithm terminates, the two pointers are examined simultaneously with all sizes,
so no empty vector corresponds to any potential element that appears in both lists.  
By Lemma&nbsp;2, all elements that appear in both lists are printed exactly once.  
Therefore the output definition is satisfied. ∎

### Complexity analysis

*Time*:  
Sorting the two arrays is *O(n log n)*.  
The single‑pointer loop is *O(n)*.  
So the entire algorithm runs in *O(n log n)* time.

*Space*:  
Sorting the arrays in-place provides no additional storage for the two arrays.  
We only use a few integer variables (`i`, `j`, `n`, `n` control variables).  
Thus extra memory is *O(1)*.
