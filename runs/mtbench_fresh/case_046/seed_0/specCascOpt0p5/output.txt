We need the median of the *union* of two already‑sorted arrays.  
The
following search must return a **median** in **O(1)** auxiliary space and **O(n)** time
where `n = max(a.length, b.length)` is the size of the larger array  
(`n = a.length + b.length` – the total number of elements – is what we need).

The simplest way is to keep the two arrays ordered in a *merged* fashion and
temporarily remember only the last two elements.  
Once we reach the middle of the merged list we can compute the median.

```
expected i = 0 …   n = a.length + b.length
```

| Step | What we do | Why |
|------|------------|-----|
| 0 | `i = 0`  and `j = 0` | Indexes of the two sorted arrays. |
| 1 | `curr = a[i]` if `a[i]` is smaller than `b[j]` (or first element left of `b`) – otherwise take `b[j]`. | Generate the next element in the merged order. |
| 2 | `prev` is the first two elements that the median is known; if the total number of elements is odd we only need the middle value; if the total is even we use the average of the two middle values. | Keep only the last two elements and use them. |
| 3 | While `i + j < n` we traverse the merged sequence, keeping one element at a time (`curr` and `prev`). | We never need **the whole array** (only one pass). |
| 4 | After the loop terminates, state (desired → median) is the `curr` if it’s the exact middle element, or `prev + curr` for even elements. | Because we don't have to store the merged whole array. |

We only need to maintain two information:  
`current` (current index) and `prev` (the smallest element that is not yet enough).  
Therefore the answer is **O(1)** auxiliary space.

The algorithm runs in **O(a.length + b.length)** time, because we are iterating the
combined number of elements once.
